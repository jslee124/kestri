## 版本、环境和检查

分支 `codex/m4-first-version`，基于 main `f82db3a23ba03f441ed3859c55f2f996e7715f2b`。Python 3.14、uv 0.12.3、macOS 主机、OrbStack Docker/Linux arm64、PostgreSQL 17，部署 Python 3.14.8。锁定 LangChain 1.4.3、LangGraph 1.2.12 不变，wheel 含迁移 1–4。Ruff lint/format、严格 mypy、双语/链接检查、构建和真实隔离 PostgreSQL 下的 122 项测试通过，**无跳过**。发布后补充 CI 与审核版本。

M4 增加 12 项生命周期测试：业务/证据实际恢复、旧备份中后来忘记/删除的数据、重新显式授权、归档/checkpoint/文件副本物理过期、清除内容但保留费用/身份和无关文件、运行租约/繁忙拒绝、不完整证据/导出拒绝、损坏/私有文件校验、受控文件失败回滚、独立备份过期、恢复后一次性积压命令丢弃、删除失败重试、符号链接边界与取消时备份租约保持至文件工作完成。部分案例含多个转换；先前测试全部重跑。

受控外部故障使用真实应用/适配器/runtime 配合模拟传输和时钟，证明指定故障转换，不证明所有断电点、真实服务故障或安全攻击。最初因 Docker 停止，数据库测试准备失败；启动后完整隔离测试通过。破坏性测试没有使用个人数据库。

## 实际部署与恢复

[M4 脱敏元数据](evidence/m4-live.json)记录健康、非 root/只读策略、挂载、网络/端口/资源检查、菜单回读和流程结果。真实运行 ID、具体时间、费用、个人数据库统计及正文仅保留在本地私有验收目录，不公开。实际基础 Compose 无数据库发布端口，应用仅挂载独立工作区，无 home/socket 挂载，移除 capabilities 并限制 CPU/内存/进程/临时空间。两服务 healthy 且使用 `unless-stopped`；不证明电脑自启动或服务商健康。

应用停止时为真实已有数据生成私有逻辑备份，恢复到**独立空数据库和工作区**，业务记录及提取证据与源内容一致。预览不导入，权限 `0600`，没有可执行的导入工作或待发送消息。[恢复元数据](evidence/m4-restore.json)仅保留检查结果，不包含私有快照或个人数据库统计。原快照事实/任务已忘记/替代/删除；活跃数据隔离及后来撤销保护另由受控案例证明。未启动隔离恢复的 Telegram poller，积压更新边界通过传输测试验证。个人部署数据保留。

## 本次个人流程试用

主人 Telegram 窗口保存一条临时全局偏好，要求简报末尾写“验收完成”。真实 DeepSeek/Tavily 研究提取 LangChain 官方资料，附来源/获取限制并应用记忆。回复该答案，区分来源事实与工程判断，没有新增网络搜索。

创建指定本地时区、即将到期的临时每日约定。到期前普通重启应用，约定和当前记忆保留。计划时刻仅执行一次后台简报并成功投递，包含来源和记忆后缀。之后暂停并删除临时任务、忘记临时记忆。最终 `/tasks`、`/memory` 无有效测试条目，没有排队/运行工作。本地估算费用已私有记录，不是服务商账单。

这是一次流程试用，不是多日连续使用。长期价值、跨多日睡眠/唤醒、服务可靠性、不同对话的摘要质量和用户反馈继续单独记录，不靠任意等待时长宣称完成。
