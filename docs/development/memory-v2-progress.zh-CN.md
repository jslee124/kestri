## 已实现提案提取

[MemoryExtractor](../../src/kestri/memory_extractor.py)实现严格、不可变的 Pydantic 来源/批次/已有记忆/提案 schema。模型调用前检查主人、开启/忘记水位、fresh/context 数量、字节准入、任务范围和来源资格。配置秘密与可识别凭据标记在发送文本前拒绝。开启的 batch 是可信 repository 快照，不是模型创建的授权令牌。

使用现有 DeepSeek/LangChain 链路，仅提供结构化 `MemoryProposal` 响应工具，无研究/执行工具、无 checkpoint saver、最多一次模型调用，复用完整输入/输出准入、费用预留/结算、外层超时、关闭 tracing、调用前后运行有效性检查。调用者须提供绑定已授权 run 的有效 Budget；后续维护 worker 须登记独立 run，并在提交事务中重查开关/版本。

应用规则检查逐字 Unicode 来源位置、fresh 直接主人归属、推断候选隔离、提供的目标/版本/类别/范围、来源时间顺序、重复操作、秘密内容与带时区时间边界。强化不能改写目标内容；近期状态无明确到期/复核时，从来源时间生成 30 天复核时间。空提案有效。返回包含捕获 batch 和归一化操作的 `ValidatedExtraction`。校验不执行 SQL 写入、不推进游标、不发送提示、不自动开启运行时记忆。

## 验证

25 个提取测试通过，包括 HTTP mock transport 上的真实框架调用：恰好一次服务请求、只有提案工具、一次预留/结算、输出完成校验。其他测试覆盖错误引用、推断写入、转发/外部来源、历史水位、主人/范围、旧替代、改写强化、秘密、无时区日期与重复/非法提案。全部本地测试 106 passed，66 个依赖数据库的测试跳过。Ruff lint/format、mypy（27 个源码模块）、文档链接/翻译检查与 `git diff --check` 通过。不证明真实模型输出的语义准确率或真实服务提取质量。

## 后续增量

迁移、持久维护 run/jobs、开启界面、候选批准、自动发布、接收来源标记、pgvector 存储、混合检索、历史工具、货币换算及生命周期/备份集成尚未实现。运行中的 Telegram bot 继续显式记忆行为。按规格顺序完成，并分别记录独立数据库、并发、评测与真实验收证据。敏感/假设内容理解仍依赖模型与后续策略分类器，逐字来源检查本身不能证明语义正确。
