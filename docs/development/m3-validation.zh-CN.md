## 真实 Telegram 记忆与重启

在主人聊天显式保存临时全局演示颜色“蓝色”，普通提问使用蓝色回答。明确按 ID 纠正为绿色，蓝色被取代。重启应用后，新问题使用当前绿色记忆。明确忘记纠正后的记录，将其标为已忘记。再次重启后，仅询问当前有效记忆的问题得到“不知道，没有可用有效记忆”的回答。随后 `/memory` 显示有效列表为空。

数据库检查确认蓝色行是 `superseded`、绿色是 `forgotten`，有效记忆、未删除任务及排队/运行执行均为零。六次验证执行完成，保存的通知/结果已发送。三次记忆控制没有调用模型，三次提问调用真实 DeepSeek，未检索网页。本地估算费用为 $0.000813，加上独立压缩材料合计 $0.002689；配置估算不等于服务商账单。

[脱敏 Telegram 元数据](evidence/m3-live-telegram.json)保留 ID、取代关系、状态、时间、用量总计与发送尝试，不含凭据、主人/聊天 ID、完整消息、推理或来源原文。临时记忆已退出活跃使用，未物理擦除。没有新建持续任务。任务范围检索与过时代次后台撤销使用受控检查验证，没有真实定时记忆简报验证。

## 限制与下一增量

只有显式记忆控制写入事实；没有自主提取、向量索引、待确认建议流程或语义纠正目标。每次成功记忆变更重置前台上下文，并排除旧代次回复/证据的自动使用，以连续性换取撤销保障。历史行、消息与 checkpoint 仍保留，原始归档可显式查看；`/forget` 不擦除它们或外部服务商副本。`/new` 保留记忆和任务。

压缩使用锁定 LangChain 中间件及经过测试的受保护方法扩展，升级依赖时应复核。完整摘要输入必须在预算内，不静默裁剪、不伪造兜底摘要、不无限重试。M4 必须完成生命周期/恢复核对、运维文档与整体个人使用试验，才可宣称完整第一版完成。
