[产品](../design/product.zh-CN.md)定义范围，[需求](../design/requirements.zh-CN.md)定义验收，[架构](../design/architecture.zh-CN.md)与[安全和数据](../design/security-and-data.zh-CN.md)定义预期机制和默认值。本文组织交付顺序，不替代这些来源。

**当前下一目标：M0。** 尚未实现或验证任何应用里程碑。M1 是首个完整 Telegram 产品流程。后续里程碑基于前面的成果，并保留已验收行为。

## 完成规则

- 安全、资源限制与必要持久化和恢复，随引入相关风险的能力一同落实。M4 汇总证据，不推迟这些控制。
- 使用稳定需求和验收 ID 关联里程碑。早期可能只覆盖某个案例的一部分，必须明确记录范围；完整案例只有全部预期行为有证据后才算验证。
- 区分受控或离线检查、真实服务、Telegram、恢复与部署观察。模拟成功不证明实际接入有效。
- 不能仅凭代码存在或一次正常流程演示就标为已验证。满足退出条件，保留证据并记录已知限制。
- 下一里程碑受影响的待决选择，在认定完成前必须解决。本文不规定准确 API、表结构、依赖版本或任务拆分。

## M0：验证模型接入

### 成果与范围

在本地运行调用 DeepSeek 官方 API 的最小 LangChain agent，提供一个确定性的受控测试工具，检查真实模型请求、工具结果和回答循环。在 Telegram 与网页获取引入更多环节前，先确认接入行为。

### 退出条件

- 真实模型请求工具、消费结果并生成相关回答。
- 多轮交互保留必要服务状态。验证选定思考模式，记录使用的模型标识符与依赖版本。
- 工具失败、服务失败和配置的调用或时间上限，都产生有边界且易于理解的结果。
- 通过本地配置加载凭据，提示词、输出和日志不包含密钥。测试工具没有任意本机访问能力。
- 保留调用元数据和可用用量，不宣称未实际观察到的精确账单。

### 追溯与证据

为 CHAT-001、SEC-001、OPS-001 和 OPS-002 打基础，覆盖 AC-12 的模型和工具部分。保留脱敏真实交互证据与受控失败检查，不代表完整应用策略或 AC-12 已验证。

## M1：交付 Telegram 即时研究

### 成果与范围

配置好的用户在 Telegram 私聊提问，收到带来源链接的精简总结，并回复继续讨论证据。接入受控搜索和提取、限定工作区材料，以及 PostgreSQL 对话和执行记录。提供基本状态、取消与用量查看。

### 退出条件

- 模型调用或个人数据访问前完成用户与聊天授权。
- 搜索和提取保留来源，标明失败或截断材料。回答区分获取事实、解释和缺口。
- 回复关联检索相关证据。未指定目标的停止针对前台执行，取消处理后不再启动新工作。
- 正常重启保留已接受消息和对话状态。重复入站更新不重复执行已接受的状态变更。
- 从本里程碑开始执行工具、路径、URL 边界与配置的调用、时间、输出和费用限制。来源指令不能扩大访问。
- 原始消息独立于 agent 状态保存，为后续压缩提供原始归档。

### 追溯与证据

重点：AUTH-001、CHAT-001、CHAT-002、WEB-001、WEB-002、SEC-001、SEC-002、DATA-001、OPS-001 和 OPS-002。

完成 AC-01 和 AC-02。收集 AC-05 的前台部分、AC-07 的入站和对话部分、AC-09 的回复部分、AC-10 的研究边界部分，以及 AC-12 的限制和用量部分。保留真实 Telegram 和模型服务证据、来源材料，以及受控边界和重启检查。后台、记忆和完整案例结果仍待验证。

## M2：交付持续简报

### 成果与范围

用自然语言创建持续新闻简报，回显约定，在同一个聊天中接收结果。支持查看、修改、暂停、恢复、删除，以及停止单次执行。后台执行采用独立上下文，任务约定、执行、保存结果和发送均有持久状态。

### 退出条件

- 根据明确完整的请求只创建一个任务。时区缺失或控制目标有歧义时，修改状态前先澄清。
- 应用任务级偏好，不改变全局回答风格。
- 暂停阻止后续启动，当前执行继续；停止执行与删除持续任务是不同操作。
- 停机后遵守配置的补跑规则，合并符合条件的错过执行，不连续发送历史简报。
- 有限重试临时失败，发送失败时复用保存结果，记录发送不确定性。不宣称保证恰好发送一次。
- 重启后恢复已接受的任务变更和执行结果。后台工作不占用全部前台处理能力，也不能越过已保存授权。

### 追溯与证据

重点：CHAT-002、TASK-001、TASK-002、TASK-003、TASK-004、TASK-005、TASK-006、任务级 MEM-001、CTX-001、DATA-001、OPS-001 和 OPS-002。

结合 M1 的前台行为完成 AC-03 至 AC-07。为 AC-09 增加后台和回复行为，为 AC-10 增加任务授权检查，为 AC-12 增加后台限制和失败通知。证据包括持久化约定、可控时钟和故障检查、重启观察与真实 Telegram 发送。记忆、压缩和其他未覆盖案例部分仍待验证。

## M3：交付个人记忆与上下文管理

### 成果与范围

显式保存、查看、纠正和忘记个人记忆，在对话和持续工作中检索相关记录。自动压缩较早对话状态，同时保留原始消息，让任务证据与主对话保持分离。

### 退出条件

- 回执明确实际保存或修改的内容，保留来源、范围、时间与状态。
- 推断偏好在同意前只作为建议，任务偏好不自动变为全局偏好。
- 已忘记或取代的记录不再影响检索，不从保留历史或缓存摘要中重新构建。
- 强制压缩仍保留当前决定、纠正、约束和近期完整工具交互；保留的原始消息可以检索。
- 记忆、压缩和来源内容不能创建任务授权或改变工具权限。正常重启后相关记忆仍在。

### 追溯与证据

重点：MEM-001、MEM-002、MEM-003、CTX-001、CTX-002、SEC-002、DATA-001 和 DATA-002。

完成 AC-08 和 AC-09。为 AC-10 增加记忆和摘要攻击，为 AC-11 增加活跃记忆删除和重新提取检查；备份恢复覆盖留到 M4。保留记忆和来源记录、组装上下文检查、强制压缩检查与重启观察。

## M4：完成第一版个人使用验收

### 成果与范围

通过 Docker Compose 运行约定的第一版，覆盖三个用户流程、可查看运行，以及经过验证的恢复和数据生命周期行为。提供不需要了解设计讨论也能跟随的说明。

### 退出条件

- 全部 22 条需求和 AC-01 至 AC-12 都有完整且可链接的证据。补齐此前部分覆盖的案例，对已有流程做回归检查。
- 验证实际部署挂载、数据库暴露、凭据和资源边界。仅开发模式检查不证明部署隔离。
- 验证保留、删除、备份和恢复，恢复检索或调度前处理已忘记记忆和已删除任务。
- 在集成产品中展示有限失败、取消、重启、补跑、发送不确定性与用量查看。
- 增加经过验证的中英文安装教程、运维操作指南和配置参考，说明部署前提、外部服务使用和剩余限制。
- 记录个人试用及其发现。试用时长待确定，试用不替代验收证据。

### 追溯与证据

全部需求；完成 AC-01 至 AC-12，包括 DATA-002 和 AC-11 的完整恢复覆盖。保留发布验收记录，链接部署、真实服务、失败恢复和数据生命周期证据。说明实际测试过的环境和服务，并列出剩余验证缺口。

## 更新进度

状态使用 `尚未开始`、`进行中`、`已实现；待验证` 或 `已验证`，对应英文 `Not started`、`In progress`、`Implemented; verification pending` 和 `Verified`。两个语言版本一起更新。已验证里程碑记录代码版本、执行日期、测试环境、需求和案例覆盖、证据位置及已知限制。

证据可以是脱敏记录、针对性检查结果或可复现人工观察，根据声明选择形式。不保存 API key、token 或无必要的个人数据。未完成案例部分明确保持待验证。未来顺序或范围调整通过文档变更记录，同时保留需求追溯。
