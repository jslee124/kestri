# 创建持续简报

[English](recurring-briefing.md) · [文档](../README.zh-CN.md)

更新日期：2026-10-01。范围：M2，见[验证记录](../development/m2-validation.zh-CN.md)。

## 准备运行中的机器人

完成 [Telegram 配置](telegram-research.zh-CN.md)。保持本地应用和 PostgreSQL 运行。在请求中写明 IANA 时区，或本地配置 `KESTRI_OWNER_TIMEZONE` 并重启应用。电脑时区不是隐式约定。

## 委托简报

发送：`每天 08:00 Asia/Shanghai 给我 AI 和科技新闻简报：最多三项，每项两句话，并附实际读取的来源链接。`

检查返回约定：任务 ID、内容、每日时间、时区、状态与错过执行规则。完整请求直接创建一项任务，不再重复询问批准。缺失或不支持的信息会引发澄清，不修改任务；补充后重新发送完整请求。`/tasks` 列出保存的约定。

下次计划时刻，Kestri 在独立上下文中执行保存的请求，再把最终简报发到同一聊天。简报执行期间可以继续聊天。公开来源与预算边界与普通研究相同。休眠、断网或应用停止会延迟投递。

## 修改和控制

回复任务约定或简报：`让这份简报更短一点`，或 `把这份简报改到 09:00`。检查新约定。变更属于该任务，不修改全局偏好。

回复 `暂停` 阻止后续启动；已运行的简报继续。回复 `恢复` 从下次计划时刻启用后续执行。停止一次正在执行的后台工作，在 `/runs` 获取执行 ID，再发送 `/stop RUN_ID`；停止不删除约定。单独 `/stop` 针对前台工作。

回复 `删除`，或发送 `删除任务 TASK_ID`，移除后续调度。已删除约定保留历史/证据；M2 没有物理归档删除。存在多项任务时，歧义请求会引发澄清。回复汇总的 `/tasks` 列表不能选择某一项。

## 观察重启行为

使用相同 PostgreSQL 和工作区卷重启应用。约定保留。默认六小时补跑规则每项有效任务最多补跑最近一次错过的简报，不逐日重放全部错过执行。更早的错过执行跳过。暂停/删除任务不补跑。

用 `/status`、`/runs`、`/usage` 检查结果与估算。已知发送失败重试保存文本；不确定发送保持待核对。进程中断的研究报告中断，不盲目重启。准确的限制、重试和夏令时行为见[任务参考](../reference/tasks.zh-CN.md)。
