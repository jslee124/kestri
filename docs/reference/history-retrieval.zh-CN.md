## 可用性与同意

Memory v2 功能分支仅在 `/memory auto on` 和 `/memory use on` 都有效时，为前台研究注册 `search_history` 和 `read_history_segment`。首个增量明确将历史可用性与自动提取同意绑定。关闭 auto 暂停历史工具，但已有个人事实仍可使用。改变 auto on/off 清空前台指针并推进上下文 epoch，防止旧历史工具消息带入新的同意阶段。重新开启 auto 设置新的归档水位，不回填旧历史。恢复关闭 auto/use，因此导入的历史不能被自动检索。

开启回执说明之后的聊天可按需发送到 DeepSeek，用于回答历史问题。词项搜索及读取不调用服务商；显式开启的历史语义召回以 `history_retrieval` 预留并记录 embedding 费用；后续模型调用及摘要仍受现有账本限制。工具返回内容可保存为该 run 图 checkpoint 中的工具消息，并出现在摘要/回答中；与临时注入的个人事实不同。epoch 失效、来源保留清理和 checkpoint 清理仍适用；撤销无法收回已发送给服务商的请求。`/history` 仍是独立的主人主动归档查看入口。

## 工具契约

`search_history(query, before?, after?, limit=5)` 拒绝未知字段、空白 query、超过 500 字符的 query，以及 1–5 之外的 limit。可选日期为带时区的 ISO-8601 字符串，最多 40 字符；`after` 包含边界、`before` 不包含边界，且要求 `after < before`。主人、run 和任务身份由应用注入，不接受模型参数传入。

搜索仅覆盖指定时间范围内最新最多 200 个合格主人轮次，严格早于当前 run。来源须属于当前主人直接入站消息、未标记历史到期的前台 run、ID 同时高于开启及忘记水位，范围为全局/当前任务。排除转发、legacy、外部来源、控制指令、后台及当前 run。助手上下文只能来自同一合格主人轮次的 run。每轮最多 12 条完整消息、8000 正文字符；单条超过 24000 UTF-8 字节或整轮超限，整轮跳过。含已配置密钥或共享凭据模式的轮次同样跳过；这不保证识别全部敏感信息。

排序复用中文重叠双字词项及 ASCII 词项的正匹配 IDF 权重。语义召回同时开启且配置可用时，用精确余弦候选与词项候选执行 RRF（k=60）融合。两条链路都不用最近轮次填充零匹配。缺少 pgvector、合格索引、配置或服务可用性时退回词项结果。结果明确说明覆盖有限：空结果不证明完整归档中不存在内容。最多五个结果包含 400 字符主人节选、截断标记、日期、消息数量和来源句柄。命中可能来自已标注的助手回复；主人节选不被视为所有命中词项的证据。

`read_history_segment(segment_id)` 只接受**同一 run** 内搜索发出的 SHA-256 句柄。句柄对有序消息 ID、Telegram ID、角色、UTC 日期及完整内容计算指纹。应用内存保留句柄、主人来源 ID 和同意版本；它用于检测变化，不是授权令牌或可跨 run 使用的归档标识。读取重新加载完整轮次，检查范围/水位/同意/当前 epoch/历史到期，验证指纹，并在返回前复查设置。内容修改、来源删除、不同 run 或同意变更都拒绝访问。完整结果区分主人陈述和助手提议，绝不静默截断正文。

## 限制与生命周期

两个工具计入已有 run 总工具调用上限及超时。JSON 输出须满足 `tool_output_chars`；读取超限直接拒绝，不裁剪历史事实或返回损坏 JSON。搜索在较小配置上限下减少节选数量。schema 与返回消息进入下一次模型请求的正常准入检查。历史不会创建事实、授权任务或提供任意文件/主人访问。系统提示将历史视为不可信、带日期的证据。

迁移 7 新增可选 `history_embeddings`，只保存来源 ID/hash、配置代次及 1024 维向量，不复制聊天正文。来源新增/修改/删除、run 历史到期及同意/水位/编码空间改变使缓存失效。逻辑备份当前为 schema 7，省略此可重建表；恢复要求派生索引为空，并关闭 auto/use/semantic。来源保留清理移除访问，较广 epoch 重置防止旧图复用。忘记推进现有自动历史截止水位。句柄在 run 结束/重启后丢弃；重试必须重新搜索。搜索在发出句柄前复查选中来源，读取校验来源 hash。数据库读取无法撤回已交给调用方的正文；后续模型请求和结果发布前仍有 epoch/活动检查。

## 渐进语义覆盖

`HistorySemantic` 在每个前台 run 的首次语义搜索中，为最新最多九个尚未索引的合格轮次建索引；查询与完整轮次编码合为一次请求，最多十个输入。编码使用带角色、来源 ID、日期的完整消息 JSON，并使用独立版本化空间指纹。JSON 超过 8192 UTF-8 字节的轮次仍只用词项，不截断正文建索引。发布索引时在主人/来源锁内复查设置、epoch 及完整来源 hash。向量排序与发出句柄前也验证当前合格轮次的 hash。并发追加可能使编码过时；指纹不匹配的记录不能成为候选。

每 run 最多尝试三个不同查询的 embedding，成功查询向量可复用；新增轮次索引只尝试一次。embedding 使用配置的记忆检索期限（默认十秒），费用纳入前台 run 与主人预算，沿用 CNY 换算元数据并标注 `history-complete-messages-json-v1` 输入配方。费用元数据不保存服务正文/向量。失败使用固定类别并本地降级；已提交而状态未知的请求保留预留。取消/epoch 改变阻止输出及缓存发布，已知成功用量仍记录。

精确余弦阈值使用独立的 `KESTRI_HISTORY_DENSE_MIN_SIMILARITY`（默认 0.60，范围 -1–1）。完整消息 JSON 需要独立校准，不能套用个人事实的评测阈值；不增加额外筛选模型调用。结果提供 `method`、`indexed_turns`、`eligible_turns`、`fallback`；语义覆盖只包括当前合格的已索引子集，候选窗口最多 200 轮，最多二十个向量候选及五个融合结果。重启保留向量，但丢弃 run 内查询/句柄缓存。历史向量是派生证据，不是个人事实。阈值校准、中文标注质量评测及真实验收仍待完成。[语义历史测试](../../tests/history/test_semantic_history_integration.py)覆盖受控纯向量召回、查询缓存、限制、失败/记账、来源/设置失效、在途撤销、真实图搜索/读取及备份/恢复。

## 持久后台索引

迁移 8 增加 `history_index_jobs`。新主人消息与助手回复的归档同事务登记/更新作业；开启语义或 use 时只登记高于自动开启/忘记水位的合格直接来源，升级也仅登记已同意的来源，不扫描开启前历史。来源变化增加 `source_revision`，撤销旧租约/run/预留后重新排队；来源删除将 owner FK 设空并取消在途作业，run 历史到期同样撤销。auto/use/semantic 任一关闭或代次/水位变化都会取消旧作业。消息、设置及索引作业是同一数据库提交边界。

`Application.memory_maintaining` 顺序运行提取、事实索引、历史索引三个维护组件。历史 worker 仅在主人前台没有 queued/running 工作时领取，按创建顺序每轮一个作业。租约 120 秒，过期可重新领取；最多三次尝试，临时网络/429/5xx/超时重试间隔 5/30 秒。无效/超大/凭据片段不发送；服务拒绝或预算耗尽终止。来源版本、代次、租约和当前范围在领取、计费及提交时检查，旧租约不能发布或覆盖新版本状态。无关 epoch 变化导致提交拒绝时允许有限重试，不沿用旧输入。

`history_index` 与 `memory_extract`/`memory_index` 共享 UTC 月维护预算（默认 1.50 USD），每个来源版本的维护 run 全部尝试共用默认 0.15 USD 上限，同时受主人总月预算约束。沿用 CNY 预留、实际用量及未知请求保留策略。每次只编码一个完整轮次，最多 8192 UTF-8 字节；前台按需编码/查询仍使用前台预算。后台检测已有匹配向量时标记成功，不再次请求服务。查询时间窗口仍最多 200 个合格轮次，但后台作业覆盖水位后所有合格来源，不限于九个查询时新片段；覆盖不保证立即完成、也不覆盖超限/预算拒绝来源。

发布向量、作业成功与 run 完成在同一事务，锁内复查完整来源 hash，HTTP 不在事务内。重启保留作业/向量，租约恢复重建当前来源，未完成预留记为未知。`/memory changes` 显示历史索引状态数量。逻辑备份 schema 7 包含作业元数据、不含正文副本及派生向量；严格接受 4/5/6/7，旧格式补空历史作业，恢复关闭全部记忆开关并取消所有历史作业。手工 `/history` 仍独立，未授权历史回填仍未开放。

[后台作业测试](../../tests/history/test_history_jobs_integration.py)覆盖前台优先、完整回复重新排队、并发领取、过期/旧租约、有限重试与共享预算、在途关闭/来源变化、删除/水位撤销、缓存免计费以及 schema 6/7 恢复。当前检查均为受控测试，没有真实私人服务商/Telegram 或中文质量达标证据。

[收尾评测](../development/memory-v2-completion.zh-CN.md)用开发集单独选阈值，并按不同项目名划分两组，将完整消息 JSON 校准为 0.60。同主题词项候选可能不含所问属性，仍需完整读取并在最终回答中说明证据缺失。这是合成校准，不是通用相关性规则。
