# 个人记忆与对话上下文

[English](memory-and-context.md) · [文档](../README.zh-CN.md)

更新日期：2026-10-02。范围：M3 实现；见[验证记录](../development/m3-validation.zh-CN.md)。

## 主人控制

所有命令出现在 Telegram 原生可折叠菜单。记忆控制由应用确定性处理，不调用模型。只有已授权主人的直接消息可写入记忆，转发指令、研究结果、推断和摘要不能授权。建议偏好需要新的显式保存指令。

| 输入 | 行为 |
| --- | --- |
| `/remember 内容` 或 `记住：内容` | 按原文保存为全局记忆 |
| `/remember task 任务ID 内容` | 只用于该任务，需要无歧义的至少八字符 UUID 前缀 |
| `/remember expires=2099-01-01T00:00:00+00:00 内容` | 显式未来、带时区的 ISO 到期时间，可在 `task 任务ID 内容` 前使用 |
| `/memory` | 查看有效、未过期条目的 ID、范围、来源 Telegram 消息、时间和到期时间 |
| `/correct 记忆ID 内容` 或 `更正记忆 记忆ID 内容` | 用新原文取代有效条目，保留任务范围和到期时间 |
| `/forget 记忆ID` 或 `忘记记忆 记忆ID` | 为一个有效条目保留删除标记并使自动上下文失效 |
| `/history` | 查看最近十条原始记录的 ID 和有上限的预览 |
| `/history 记录ID [偏移]` | 按每页 3000 字符读取该主人的原始记录，必要时显示继续指令 |

纠正/忘记需要无歧义的有效记忆 ID，不提供批量删除或语义猜测目标。保存指令正文上限 1200 字符。标明凭据的内容、可识别密钥格式与已配置秘密的脱敏标记被拒绝；这是保守过滤，不是完整敏感数据分类器。凭据不进入记忆。显式记住表示保留意图，应用不会自动推断个人事实。

## 持久化与检索

迁移 3 保存内容、来源消息/执行、全局/任务范围、创建/更新时间、替代关系、到期及 active/superseded/forgotten/expired 状态。按执行标识保存的回执与变更一同提交，重复更新和提交后重启不会重复变更。原始消息、任务、来源证据、checkpoint 与记忆仍独立。

先按主人、范围和到期过滤，再执行有上限的检索。任务记忆优先于全局，范围内按关键词匹配排序，时间作为同分排序。没有向量或自动历史提取。选中记忆只标为数据加入当前模型请求，不写入图消息状态或摘要。模型回答可能提及记忆，因此失效处理也覆盖含这些回答的对话。

每次成功保存/纠正/忘记清空前台 checkpoint 指针，并递增主人上下文版本。到期在新工作/模型访问前同样处理。其他版本的旧前后台结果和证据不再自动进入回复/读取检索，旧运行工作无法启动后续计费操作或恢复旧前台指针。已经提交的外部请求不能撤回；若其在版本变更后完成，回答会被安全的上下文停止提示替代，不再发送旧内容。这种较广的失效范围牺牲对话连续性，以防删除事实复活。`/history` 是显式只读查看，不进入模型也不创建记忆。

忘记内容保留在撤销记录、归档和历史 checkpoint，直到 M4 [保留/删除政策](data-lifecycle.zh-CN.md)移除本地副本。服务商/Telegram 副本独立处理。恢复隔离导入的活跃事实，想继续使用需重新显式保存。

## 自动压缩

锁定版本的 LangChain `SummarizationMiddleware` 选择安全切点，保留近期完整工具调用/结果。Kestri 扩展摘要调用，检查运行有效性、输入准入、输出大小、独立调用上限、费用预留/结算及外层执行超时。回归测试覆盖这段保护方法扩展，升级 LangChain 时需复核。

达到阈值时，总结较旧前缀，将近期消息留在图 checkpoint。原始消息仍在 PostgreSQL 归档。提示保留目标、决策、显式纠正、约束、未解决问题和证据引用，区分来源事实和模型推断。摘要属于历史数据消息，不是权限、任务约定或个人记忆。前后台上下文继续分离。

完整摘要输入必须满足准入限制，不静默截去旧数据。空/过长摘要、服务失败、费用耗尽、压缩次数超限或仍无法容纳的近期工具块会终止并通知，不编造后备摘要或无限重试。`/new` 新建前台上下文，保留记忆、任务和归档。摘要质量依赖模型，保留的原始记录支持显式查看。

## 配置与限制

| 变量 | 默认值 | 范围 / 含义 |
| --- | --- | --- |
| `KESTRI_MEMORY_LIMIT` | 64 | 1–64 条有效记忆 |
| `KESTRI_MEMORY_CONTEXT_LIMIT` | 8 | 每次请求 1–16 条记忆 |
| `KESTRI_CONTEXT_TRIGGER_RATIO` | 0.70 | 现有输入预算的 0.1–0.9，包含提示/工具及选中记忆开销估算 |
| `KESTRI_CONTEXT_KEEP_MESSAGES` | 12 | 4–40 条近期消息，安全工具边界可能多保留一些 |
| `KESTRI_MAX_SUMMARY_CALLS` | 2 | 每执行 1–4 次摘要调用，与常规模型调用计数分开 |
| `KESTRI_SUMMARY_MAX_CHARS` | 4000 | 500–8000 摘要字符 |

摘要调用共享单次/月度费用上限及选定的 DeepSeek 模型/输出限制。估算采用保守 UTF-8/消息框架计算，不是服务商精确 tokenizer。最终模型准入检查完整请求，包括注入记忆与工具 schema。M4 提供物理保留与隔离备份恢复，见[数据参考](data-lifecycle.zh-CN.md)。
