## 本地维护接口

`kestri data` 使用 `DATABASE_URL`、`KESTRI_TELEGRAM_OWNER_ID` 和 `KESTRI_WORKSPACE_DIR`，不需要模型服务密钥。这些是本地维护命令，不作为模型工具或 Telegram 指令提供。备份、导出、恢复和手动维护前停止应用。同一 bot 的数据库租约会拒绝运行中的维护操作；状态查询仍可在运行时使用。

| 命令 | 效果 |
| --- | --- |
| `data status` | 记录数量与最近维护结果，不输出消息正文 |
| `data backup [PATH]` | 含已提取证据的私有逻辑备份；Compose 默认 `/workspace/backups/UUID.json` |
| `data export PATH` | 不含证据原文的私有业务记录导出，不能用于恢复 |
| `data restore PATH [--apply]` | 默认验证，仅允许同一主人恢复至空数据库和空工作区 |
| `data cleanup [--apply]` | 预览或执行保留期清理 |
| `data delete-history [--before ISO] [--apply]` | 清除含时区截止时间之前的历史正文，默认清除当前全部历史 |
| `data erase [--apply]` | 清除本地内容、忘记记忆、删除任务约定和托管备份，保留最小运行标记 |

文件以 POSIX `0600` 独占创建，不覆盖现有文件。JSON **未经加密**，包含个人数据。恢复拒绝符号链接、非普通文件、其他用户可读文件、格式/版本/主人/列不符、校验失败、非法证据 ID 和非空目标。SHA-256 用于检测损坏，不认证不可信作者；只恢复可信的本人备份。每份最大 64 MiB、50,000 行；创建另有保守的 32 MiB 内容预算。更大安装需要另行审核备份方案。

## 保留和删除

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| `KESTRI_ARCHIVE_RETENTION_DAYS` | 90 | 1–3650 天 |
| `KESTRI_EVIDENCE_RETENTION_DAYS` | 30 | 1–3650 天 |
| `KESTRI_LOG_RETENTION_DAYS` | 30 | 1–3650 天 |
| `KESTRI_BACKUP_RETENTION_DAYS` | 30 | 1–3650 天 |
| `KESTRI_MAINTENANCE_INTERVAL_SECONDS` | 3600 | 60–86400 秒 |

维护在启动时及指定间隔运行。有排队/运行工作或待发送/发送中的消息时延后；内容变更时锁住对话行。持续繁忙可能推迟清理，必要时检查状态、停止应用并手动清理。

归档过期删除原始消息，清空执行请求/结果、发送正文和旧变更回执。已忘记/替代的记忆正文及已删除任务正文在各自保留截止时间后清除。活跃和隔离记忆、未删除任务约定有独立的持续保留意图。临时证据先标记过期，再物理删除；文件删除失败保留待清理标记供重试，并停止检索。详细事件独立过期。清理归档或证据时，在空闲状态下重置对话指针/版本并删除全部图 checkpoint、blob 和 write，避免摘要复活已移除数据。这会牺牲对话连续性。

保留 ID、身份绑定、去重/撤销标记、时间/状态和费用账本。`erase` 清除内容，不删除数据库/卷，也不重置费用额度。第一版没有独立的置顶结果功能：回答遵循归档保留期，原始网页遵循证据保留期。证据删除后可能保留空执行目录。

仅工作区 `backups` 下有效的 UUID 文件名备份参与托管清理，按文件修改时间判断过期。自选路径、外部副本、导出、密钥、Telegram 消息和服务商记录不在本地清理范围。备份独立过期，所以忘记的内容可能在私有备份中继续保留至过期。请自行保留异地副本并管理其保留期。

## 保守恢复

格式 `kestri-data-v1`、schema 5 包含业务表和已提取证据原文，排除 LangGraph checkpoint/内部思考和密钥。这是应用逻辑快照，不是 `pg_dump` 或完整崩溃状态镜像。schema 变更需明确决定迁移/兼容方式。

恢复隔离**所有导入的活跃记忆**、暂停**所有导入的未删除任务**，重置前台上下文，中断排队/运行工作，将待发送/发送中结果标为不确定，将未解决费用预留标为未知。已删除/忘记记录继续无效。`/memory` 显示隔离警告，想继续使用的事实需重新 `/remember`；`/tasks` 提示导入任务，仅对当前仍需要的约定显式恢复。旧备份无法静默恢复后来撤销的权限。

恢复后第一次启动 Telegram 会丢弃该边界之前的待处理更新，并发送恢复通知。请在通知后发送新指令，防止旧命令再次授权恢复数据。普通重启不丢弃更新。边界采用 [Telegram getUpdates](https://core.telegram.org/bots/api#getupdates) 的负 offset 行为，核对于 2026-10-02。

受控恢复失败会回滚数据库并删除新建证据。文件操作期间突然退出/断电可能留下孤立文件；保留源备份，检查后换空目标重试。不宣称所有崩溃点均原子恢复。参见[备份恢复指南](../how-to/backup-and-restore.zh-CN.md)和 [ADR-0006](../decisions/0006-conservative-data-recovery.zh-CN.md)。

## 自动记忆生命周期

schema 5 包含 `memory_jobs`、`memory_sources`、`memory_events`；schema 4 恢复补新列的保守默认值、新表为空。恢复总是关闭提取、增加开关代次、取消作业，隔离 active 与 candidate 记忆，不从恢复文本排入 embedding/提取。删除归档来源会级联删除引用，使依赖的自动 active/candidate 事实到期、取消受影响作业并使上下文失效。清空数据还删除全部来源引用并关闭提取。复核/到期过滤先于召回。事实与原始归档继续分离，显式事实保留独立意图。
