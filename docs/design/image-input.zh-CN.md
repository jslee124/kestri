# 图片输入

[English](image-input.md) · [文档](../README.zh-CN.md)

## 范围与体验

支持 Telegram 照片、图片文件（JPEG、PNG、WebP）、附带说明、相册，以及
“比较第 1 和第 2 张图”这样的连续追问。回复仍为文字。一个相册只产生一次研究
执行和一次接收提示。图片说明作为研究输入，不作为记忆或任务控制指令。
暂不支持动画、PDF、图片搜索或图片生成。

## 持久化接收

下载前先检查主人身份和私聊。每个更新在现有 inbox 事务中持久化。
按聊天和 `media_group_id` 合并相册；只向仍在排队且收集尚未关闭的执行追加。
最后一张收到后等待两秒，收集总时长上限十秒。Telegram 没有相册完成信号，
因此这是启发式窗口；迟到图片明确提示重新发送，不偷偷创建第二次执行。
重启保留排队收集状态和 inbox 去重。在每条消息内按 Telegram 消息 ID 编号，忽略到达顺序。
收集相册期间后到的前台文字等待相册先处理。
同一照片只选一个合适尺寸，不把缩略图版本当多张图。说明按消息顺序合并。

## 附件与模型输入

迁移 11 增加 `runs.media_group_id` 和 `image_inputs`，记录 UUID、执行/聊天、
Telegram 消息/文件 ID、说明、状态、实际 MIME、尺寸、字节数、哈希和创建时间。
文件 ID 是私有传输元数据，不传入模型。执行时通过 `getFile` 下载，使用有界流、
禁止重定向、校验 Telegram 相对路径；绝不把带 Token 的下载链接交给模型。

复用现有禁止跟随符号链接的 workspace 边界，保存私有 UUID `.image` 文件。
用 Pillow 解码并验证真实像素，仅接受静态 JPEG/PNG/WebP。最多 10 张，
单文件 10 MiB，每次模型请求合计 20 MiB，每边最多 8192 像素，每图最多
3200 万像素；限制覆盖仍保留在上下文中的图片。格式不支持、缺失、下载失败
都会终止本轮并明确提示重发，不假装已经读完全部图片。

检查点只保存文字和 `image_refs` 元数据，不保存图片字节。模型中间件校验引用
归属后，临时构造 `image_url` data 块。用离线 HTTP 传输验证锁定版 DeepSeek
序列化器。配置模型必须支持视觉；默认 `deepseek-flash` 的官方文档支持图片。
不静默切换提供商。图片内容是不可信证据，不能授予权限。

## 上下文、预算与记忆

每张图按 1024 输入 token 加普通文字和封装开销保守估算，计费调用前预留预算，
按实际 provider usage 结算。该估算针对文档中的 DeepSeek Flash 图片契约。
摘要读取已有对话与附件引用，不读取 base64 文字；保留引用以便后续重新看图。
保留图片超过附件上限时提示用 `/new`。自动记忆不能把看图推断当成主人陈述；
本版本不将图片说明加入自动个人记忆来源队列。

## 生命周期与验证

备份 schema 9 包含附件记录和经过验证的 base64 图片字节；导出也包含图片字节，
让引用可用。沿用现有备份大小限制。恢复接受 schema 4–9，补齐旧列，写入前
验证图片哈希、元数据及归属，保留现有保守隔离。待下载附件恢复为过期状态，
恢复后不自动重新向 Telegram 下载。保留期限使用证据保留期限或更早的聊天
过期时间；先持久化待清理状态再删除文件，崩溃后可继续清理。文件过期时清空
检查点图片引用；擦除同时移除传输标识与字节。

验收覆盖授权、跨轮询批次相册、重复/迟到/排序/重启、下载/格式/大小失败、
实际多图请求、追问/检查点/摘要边界、预算和备份/导出/恢复/清理。运行 Ruff、
mypy、离线和隔离 PostgreSQL 测试、双语文档与 SQL 检查、控制评估和构建。
真实 Telegram 与模型服务验收单独记录。
