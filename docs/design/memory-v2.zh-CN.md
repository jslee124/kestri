# Memory v2 规格

[English](memory-v2.md) · [文档](../README.zh-CN.md)

日期：2026-10-02。状态：已确认产品方向与实施规格；持久化、显式开启的自动提取已在功能分支实现；向量存储与混合检索已在功能分支实现；有界词项历史工具已实现，历史渐进语义缓存/混合召回已实现，持久后台索引已实现，质量评测仍待完成。独立实现的 [embedding 接入](../reference/embedding.zh-CN.md)只是前置能力。[ADR-0007](../decisions/0007-automatic-semantic-memory.zh-CN.md)记录显式记忆向自动记忆的转变。

提案提取与持久 worker 已实现，准确交付边界见[实施进度](../development/memory-v2-progress.zh-CN.md)。

## 目标与范围

Kestri 从日常主人聊天中理解有用个人背景，跨语义改写召回，并随主人改变主意更新。保留显式保存、纠正、忘记入口。首版覆盖直接个人事实、目标、偏好、决定、近期状态、候选推断、混合召回、有界历史搜索与撤销。不推断诊断/人格，不凭记忆授权任务或外部操作。成功标准是正确且有用的回忆，不只是生成向量。

## 来源与用户控制

自动提取需要主人整体开启；首次升级默认关闭，不回填旧历史。保存开启消息水位。只有开启后已授权主人的直接消息可作为自动事实依据。助手消息只帮助理解指代，不能证明个人事实。转发、外部回复、引用来源、工具和生成摘要不能授权或证明事实。接收时保存来源标记：仅凭 direction 不足以判断可信来源。直接消息中的引用和假设仍需提取阶段排除。

`/remember` 具有最明确的保留意图。自然语言纠正/忘记走独立控制解析：唯一明确目标可以提交，模糊目标展示有界候选并等待选择。不能把任意模型选择的 ID 当成授权。普通新增可显示简短变更提示，重复强化静默处理。提示经当前 epoch 校验与持久 outbox 投递，不在提取事务里发送。

计划接口：`/memory`、`/memory pending`、`/memory changes`、`/memory auto on|off`，以及独立的记忆使用开关。关闭提取取消待处理工作并拒绝在途提案提交，但不停止使用已有记忆。关闭使用停止记忆/历史注入。重新开启设置新水位，除非另行授权历史回填。凭据永不提取；敏感个人信息需要明确保留意图。保守定义敏感类别并评估分类器，不承诺识别所有敏感信息。

## 逻辑数据模型

PostgreSQL 来源记录是依据。核心画像是有效稳定记忆的查询视图，不另存一份生成事实。扩展 `memories`：`category`（`preference/background/goal/decision/current_state`）、`origin`（`explicit_command/auto_direct/auto_inferred`）、`revision`、`fact_key`、`valid_from`、`review_after`、`last_source_message_id`。保留标识、范围/任务、替代关系、到期、来源与现有 active/superseded/forgotten/expired/quarantined 状态，增加 candidate。自动内容是一条最多 600 字符的原子事实；保留现有显式指令 1200 字符契约。`fact_key` 是归并提示，不是唯一约束或等价证明。任务范围须有已知主人关联，不能从普通文字猜测任务 UUID；项目标签可作为元数据，不能授予任务范围。

新增 `memory_sources(memory_id,message_id,quote,start,end)`，外键指向本地 `messages.id`；偏移采用 Python Unicode 字符位置。通过关联检查主人与来源资格，另外保留 Telegram 消息 ID。新增 `memory_jobs`（类型、主人、来源 ID、水位、捕获的 revision/epoch/设置版本、状态、租约、次数、下次时间、安全错误类别、唯一幂等键、维护 run ID）、`memory_events`（操作、ID、版本、原因类别、job ID、时间）与 `memory_embeddings`（记忆 ID、内容版本/hash、向量空间、向量、时间）。事件不能无限重复保留被忘记正文。

主人状态增加 `auto_memory_enabled`、`memory_use_enabled`、`memory_revision`、`automatic_history_floor`、开启水位和设置版本。现有 `memory_epoch` 继续用于撤销。候选推断不作为确定事实注入。建议容量：每主人 1000 条有效记忆、100 条候选，不静默淘汰显式记忆。容量不足延期新增并显示维护状态，替代/强化仍可执行。这些容量只在功能交付时替代当前 64 条上限。

## 提取输入与输出

接受消息和登记作业同事务提交，不能依赖回答成功投递。前台占用资源时后台延期；即使回答失败，也可学习主人事实。按来源 ID 时间顺序处理。每批最多 8 条新增主人消息、总共最多 12 条相邻上下文消息、来源文本最多 24000 UTF-8 字节。所有历史，包括助手上下文，都应用开启/撤销水位。单条超限仍归档，标记提取不适用与安全原因，不静默截断事实。另外读取最多 20 条相关已有记忆，设独立输入额度；最终准入包括 schema 和指令。

模型返回严格 Pydantic schema，最多 8 个操作。字段：action（`create/reinforce/replace/candidate`）、可选目标 ID 与预期版本、category、content、fact_key、scope、basis（`direct_statement/inference`）、来源 ID 与逐字引用及位置、生效/到期/复核时间。无任意 SQL、工具、删除、任务授权或可执行指令。直接陈述可生效，推断只能进入候选；模型自报置信度不是校准概率。候选生效需要主人动作，反复模型猜测不能自动升级。

提交前检查 schema/大小、引用原文及位置、批次归属、主人、来源资格、秘密过滤、目标状态/范围/版本、时间顺序与时效。引用校验只证明来源存在，不能证明语义理解正确。模型提出，应用校验并事务决定。没有操作的成功作业也推进处理游标。

## 归并与时间语义

新直接事实用 create；真实等价事实用 reinforce 增加独立来源；明确改变属性时插入新行并替代旧行。可共存的偏好分别保留。模糊冲突进入候选，不覆盖确定事实。推断不能替代显式记忆。旧输入不能覆盖新陈述，使用最新来源 ID 与版本检查。不能仅凭模型生成 fact_key 就认定替代安全。

明确时间边界转为到期时间；模糊近期状态建议 30 天后复核，不编造确切到期日期。超过复核时间，不进入普通当前状态注入，历史回忆可带日期描述。稳定事实不自动到期。访问/提交时检查到期。按主人时区解释并用 UTC 存储，相对时间以来源消息时间为依据。

## 检索与上下文组装

每次模型请求取得一致的有效记忆快照。最多选择 6 条直接稳定交流偏好、共 2000 字符；相关事实最多 8 条，全部记忆注入合计最多 6000 字符。不用零命中近期记忆补满。显式保存不表示所有问题都相关。

查询使用当前请求及最近最多 4 条对话，共最多 4000 字符；首版直接使用该文本，不增加查询改写调用。先按主人、有效状态、范围、任务状态、到期、复核时间和内容版本过滤，再精确搜索。关键词与向量各取最多 20 个候选，用 Reciprocal Rank Fusion（`k=60`）合并，随后一次有界模型选择仅返回有效候选 ID，允许空集合。定义并锁定中文分词/双字检索实现，不假设 PostgreSQL 默认语言配置足以支持中文。向量阈值归属特定模型/编码空间，以评测校准，不能使用通用阈值。

注入前重查状态、内容版本、设置版本和 epoch。revision 改变时重做一次本地选择，撤销时终止旧工作。选择模型输入最多 12000 UTF-8 字节，前台失败不重试，计入前台预算。超时、未知用量或服务错误降级为有界关键词检索，不伪造语义分数。记忆标为带来源的不可信数据，不是授权；不写进图消息，但模型回答可能复述。

## Embedding 与存储契约

初始服务：北京 DashScope `text-embedding-v4`，1024 维 float。[已实现适配器](../reference/embedding.zh-CN.md)使用业务空间兼容接口，每次最多 10 条文本、有界响应，检查索引/维度/有限非零向量及用量。记录准确编码方法；以后改为原生 query/document 模式要作为新空间处理。`embedding_space` 包含服务商、地域、模型、维度、编码方法和应用版本。模型 alias 可漂移，需监测探针和保留索引代次，不能宣称服务商权重不可变。

原文先写入，与向量作业入队原子提交。事务外生成向量，仅在记忆仍有效且内容版本/hash 一致时提交。唯一键避免重复索引；陈旧/孤立计算可能收费，但不能恢复事实。没有向量的版本仍可关键词检索。初期 pgvector 精确余弦搜索，测量规模/延迟/召回后才增加 HNSW。服务器先安装扩展再执行 `CREATE EXTENSION`，接入验证不自动更换个人数据卷。

向量存现有数据库独立 `vector(1024)` 表，关联当前事实。查询约束向量空间与内容版本。同维度不同模型不能比较。更换服务/模型/编码方法建立独立代次，验证后切换，不能混用。启用存储前明确迁移/upsert SQL 与删除测试；当前未交付向量 DDL。

## 历史检索

计划工具：`search_history(query,before?,after?,limit<=5)` 与 `read_history_segment(segment_id)`。主人由应用提供，不接受模型传入。合格对话片段最多 12 条消息、8000 字符，按完整轮次边界拆分，保留消息 ID、角色、日期与来源 hash。超限单条跳过或另行处理，不能静默截断。工具 schema/输出与检索请求受现有工具/准入规则限制。

时间过滤后混合召回，排除已清理、隔离、水位之前的内容。搜索返回节选与来源句柄，读取时重查资格。主人决定须有主人依据，助手提案保留提案归属。初始索引从开启点开始，历史回填是独立授权的操作，必须遵守撤销/水位规则。`/history` 仍是主人主动查看、不进入模型的归档入口。历史片段及向量不等同个人事实。

## 作业、并发、计费与失败

每主人一个提取提交通道。状态 `queued → running → succeeded`，或 `running → retry_wait → running`，最后 failed/cancelled。行锁领取、有时限租约；建议租约 120 秒、服务超时 20 秒、最多 3 次总尝试，重试间隔 5/30 秒。恢复领取过期租约，HTTP 期间不持有数据库事务。幂等键包含主人、作业类型、来源范围/hash 和提取版本。提交比较捕获的设置/revision/epoch 与目标行版本。冲突重建输入，最多重建 3 次，再延期为新作业且不丢来源进度。变更、事件、游标、作业成功同事务提交。

需新增独立维护 run 类型，因为现有 usage 外键依赖 runs。HTTP 前为提取/索引预留费用，同时检查主人月度总额和独立维护上限；建议维护每 job 1 元、每月 10 元，前台选择受前台 run 上限限制。实施前确定账本币种/转换规则：当前为微美元，服务商按人民币计费，不能直接相加；保留配置换算率/版本与原币估算，未知用量保守占用预留。免费额度不绕过本地预算。当前接入没有后台维护账本，smoke 是主动执行的一次收费请求，报告用量但不进入数据库账本。

仅有限重试瞬时错误，鉴权/schema 错误需要操作员处理。前台不等待提取。日志保存数量、版本、耗时、安全类别和用量，不保存完整提示/密钥/向量。暴露作业与索引状态。建议提取 SLO：服务正常、有空闲容量与预算时 60 秒内处理合格消息；这是验收目标，不是当前保证。

## 撤销与生命周期

新增/强化递增记忆 revision，不重置对话。替代/纠正/忘记/到期继续保守递增 epoch 并清空 head。现有模型/工具/完成检查继续拒绝旧代次。自然语言控制与提取串行提交，使在途提案失效。

首版忘记同时把主人的自动历史截止位置推进到当前最后一条归档消息 ID。自动提取、历史搜索/读取、供提取使用的摘要与索引重建均排除截止位置及之前消息，作业提交时重查。无关有效记忆仍可用；回执说明较广的旧历史自动回忆损失。`/history` 显式查看仍可用。截止位置后新的直接陈述可以重新产生记忆，不依赖语义墓碑分类器保证不复活。

删除来源需在明确事务中失效关联自动事实、历史片段、向量、缓存与图状态；显式保留事实可按现有保留意图持续存在，但被清理来源引用不能残留在 source/event 表。忘记/替代正文和原始历史遵循保留期，不等于立即全局物理擦除。证据/文件与服务商副本分别治理。交付前升级备份结构/版本，一致快照包含作业/设置/开启水位/截止位置/事件，不含可重建向量。恢复关闭提取/使用，隔离事实，清空 checkpoint 和派生索引，取消维护作业；显式开启后才恢复使用，不能恢复后自动扫描旧历史。

## 验收与交付

确定性测试覆盖来源排除、逐字引用、候选隔离、范围访问、接受/作业原子提交、重启/重复领取幂等、旧更新/关闭/忘记竞态、向量故障与陈旧提交、恢复隔离、清理依赖和预算预留。主人隔离/撤销案例必须全部通过。真实服务证据与 mock、PostgreSQL 集成证据分别记录。

维护至少 100 条中文标注评测，覆盖语义改写、指代、临时情绪、假设、引用、冲突偏好、历史决定及无相关记忆问题。建议门槛：有效事实准确率 ≥95%、直接事实提取召回 ≥85%、语义 Recall@8 ≥90%、无相关记忆错误注入率 ≤5%；记录语料、标注、分母与评分版本。一次 embedding smoke 比较不能证明整体记忆质量。

交付顺序：(1) 独立 embedding 接入及文档，已实现；(2) 开关/来源/jobs/自动提取与语义事实存储，离线及独立数据库检查；(3) 模型路径混合召回与并发/生命周期；(4) 历史工具与评测；(5) 隔离的真实 Telegram、重启/忘记/恢复验收。模块划分为 `MemoryExtractor`、`MemoryRepository`、`MemoryRetriever`、`HistoryRetriever` 与维护 worker。后续增量满足门槛前，产品继续使用显式记忆。

已实现的提取使用 0.15 USD/作业和 1.50 USD/月上限，因为当前仅调用 DeepSeek。上文 CNY 换算仍是后续 embedding 要求。每作业 1 条新消息、最多 3 次总尝试（包括冲突），耗尽后可见失败，不无限重新入队。`/memory changes` 为只读入口，自动变更通知和独立使用开关仍暂缓。准确差异和部署/评测边界见[进度](../development/memory-v2-progress.zh-CN.md)。

迁移 6 已实现语义存储/索引及有界混合模型链路，准确行为见[运行参考](../reference/semantic-memory.zh-CN.md)。新增独立语义开启和使用开关，对称 L2 编码空间指纹，按 0.5 CNY/百万与带版本固定 0.15 USD/CNY 估算，每 run 至多一次服务筛选，新增版本冲突只本地重选。这些是明确的实施选择；向量/偏好校准、历史工具和真实验收仍待完成。

历史工具首个增量见[运行参考](../reference/history-retrieval.zh-CN.md)：只做有界本地词项搜索，auto/use 同时开启时可用，auto 改变重置上下文。完整历史混合检索仍是上述目标。
