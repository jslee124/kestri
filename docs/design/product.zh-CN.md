# 产品定义

[English](product.md) · [文档](../README.zh-CN.md)

更新日期：2026-10-01。状态：产品方向已确认；尚未实现。

## 定位

Kestri 是一个在本地运行、通过 Telegram 远程交互的通用个人 AI agent，将用户主动发起的对话与明确委托的持续工作结合起来。它旨在成为有日常使用价值的个人助理，同时提供 agent 应用工程实践和可展示的求职作品。

初始用户是项目作者。第一版通过 Telegram 私聊服务一个配置好的用户。多用户托管、组织账号和商业运营不属于初始范围。

## 产品原则

- 从实际日常使用开始，在流程需要时增加能力。
- 提供可复用的信息工具。新闻是首个场景，不是固定的垂直产品定位。
- 让用户控制持续任务与个人记忆。
- 让任务约定、结果、来源与失败可以检查。
- 通过应用代码和隔离边界执行权限限制。
- 分别说明本地运行与外部 API 处理这两个产品属性。

## 初始用户流程

### 研究问题

用户提出日常问题或要求比较。Kestri 对需要一定时间的工作给出简短回执，搜索公开来源、读取相关材料，然后提供精简总结与支持链接，区分来源事实、自己的解释和证据缺口。

可以执行的请求直接推进。只有缺失信息会明显改变结果时才澄清，其余假设明确说明。用户可以追问、回复某条结果或停止当前执行。通常不为每次工具调用发送进度消息。

未指定目标的“停止”针对当前前台执行。回复已知执行消息发出的停止请求，针对该次执行。目标仍不清楚时，操作前先澄清；停止一次执行不删除其持续任务。

### 委托持续简报

用户用自然语言要求持续简报。必要信息和用户时区齐备后，Kestri 创建任务并回显约定，不额外增加重复的批准步骤。回执说明执行时间、时区、内容偏好和错过执行时的处理方式。

用户可以查看、修改、暂停、恢复和删除任务。回复任务消息可以帮助确定目标；仍有歧义时需要澄清。每次执行使用独立内部上下文，并在同一个 Telegram 聊天中发送结果。

暂停阻止后续定时启动，正在执行的任务继续完成。停止当前执行是独立操作。正常后台运行只发送最终简报，最终失败发送一次简短通知。明确针对某份简报的偏好保留在任务范围内。

### 管理个人记忆

用户明确要求 Kestri 记住偏好或事实。Kestri 回显实际保存的内容。用户可以查看、纠正和忘记这些内容。相关记忆可以影响未来的对话和任务。

第一版中，推断出的偏好必须先提出建议并获得用户同意，才能保存。记忆不授权新任务或新访问。忘记记忆后，不得从仍然保留的旧对话中自动重新构建它；删除相关历史是另一种数据操作。

## 第一版范围

| 包含 | 后续再考虑 |
| --- | --- |
| Telegram 文本对话与回复关联 | 桌面 GUI、TUI、语音、群聊 |
| 公开网页搜索、提取、总结和来源链接 | 交互式浏览器自动化与登录态浏览 |
| 持续任务和新闻简报验收场景 | 未经请求主动生成目标 |
| 显式个人记忆与用户管理 | 默认自动挖掘偏好和向量检索 |
| 上下文压缩与持久化重启恢复 | 任意 shell、脚本、插件和电脑操作 |
| 工作区成果和有边界的运行记录 | 广泛访问现有本机目录和修改已连接账号 |
| 任务取消与用量查看 | 自动多模型路由和多 agent 编排 |

专用工作区保存研究材料和生成成果。导入敏感原始文件或增加本机只读目录，需要后续访问设计，不是初始流程的前提。

## 成功标准

用户能在一个聊天窗口使用三个流程，了解保存了什么、委托了什么，并检查结果产生的依据。重启后保留任务约定与个人记忆。通过保留的运行记录，可以解释失败、取消和恢复行为。

详细验收标准见[需求](requirements.zh-CN.md)。成功必须有实际验证证据支持；单次演示不能证明可靠性或隔离有效。

## 尚未确定的产品问题

- 首次个人试用的实际简报主题和发送时间。
- 任务列表、记忆列表与运行控制的具体展示方式。
- 删除历史、导出和恢复数据的交互。
- 如何传达发送状态不确定，避免重复或过量通知。

这些问题不改变已确认的产品定位。[可运行里程碑](../development/milestones.zh-CN.md)定义增量交付与完成条件，详细实施日程不属于本产品定义。
