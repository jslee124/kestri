# 需求与验收标准

更新日期：2026-10-01。状态：基于已达成共识产品行为的规格草案。**AC-01、AC-02 已在 M1 验证；其他完整案例仍未验证。** 见 [M1 证据](../development/m1-validation.zh-CN.md)。 [M0 证据](../development/m0-validation.zh-CN.md)仅覆盖初始模型和工具基础及 AC-12 的一部分。

## 解释规则

本文将[产品范围](product.zh-CN.md)转化为可审查的第一版需求。“必须”表示交付验收条件，不表示已经实现。标识符在两种语言和后续实现变更中保持稳定。

数值默认参数统一维护在[架构](architecture.zh-CN.md)与[安全和数据](security-and-data.zh-CN.md)文档中。它们是可调的初始值，不是服务上限或经过验证的性能目标。

## 功能与质量需求

| ID | 需求 |
| --- | --- |
| AUTH-001 | 只接受允许的 Telegram 私聊中配置好的用户 ID 发来的请求。被拒绝的请求不得触发模型调用、读取个人信息或修改状态。 |
| CHAT-001 | 直接执行可以推进的研究请求。只有缺失信息会明显影响结果时才澄清，否则说明假设。对需要一定时间的工作提供简短状态，并支持停止前台执行。 |
| CHAT-002 | 将回复关联到相关结果或执行。未指定目标的停止针对当前前台执行；回复已知执行的停止针对该次执行。如果任务控制目标仍有歧义，修改状态前必须澄清。 |
| WEB-001 | 搜索公开来源、提取相关网页，并提供有支持链接的总结。保存来源，区分来源事实、解释和证据缺口。不得仅凭搜索摘要就宣称已经读取完整网页。 |
| WEB-002 | 对网页请求和模型可见材料设置时间与大小边界。说明提取失败、截断和证据不足。不得编造成功获取或无限搜索。 |
| TASK-001 | 只有用户请求授权且必要信息完整时才能创建持续任务。持久化并回显时间、明确时区、内容要求与错过执行时的规则。完整请求不需要重复的创建批准。 |
| TASK-002 | 允许用户查看、修改、暂停、恢复和删除持续任务。通过回复关联或上下文确定目标；未消除歧义时必须澄清。已删除任务不得产生后续定时执行。 |
| TASK-003 | 暂停回执发出后，不再为该任务启动新的定时执行；已经开始的工作继续。停止当前执行是独立操作。取消请求处理后，不再为该次执行发起新工作；说明无法停止的在途操作。 |
| TASK-004 | 只在已保存的用户约定范围内执行和汇报持续工作。记忆、来源文本、模型建议和时间事件不得扩大授权或创建新任务。 |
| TASK-005 | 停机恢复后采用持久化的任务级补跑规则。配置窗口内，将错过的执行合并为最多一次补跑；超出窗口则跳过，等待下一次。 |
| TASK-006 | 分别持久化执行状态与发送状态。临时失败采用有限重试；发送失败时复用已经生成的结果。记录发送结果不确定，不宣称能够保证恰好发送一次。 |
| MEM-001 | 保存用户明确要求记住的偏好或事实，并回显准确内容。记录来源、范围、时间和状态。任务专属偏好只应用于该任务，除非用户要求扩大范围。 |
| MEM-002 | 推断出的偏好建议必须获得用户同意才能持久化。推断属于候选内容，不是已确认的个人事实。 |
| MEM-003 | 允许用户查看、纠正和忘记记忆。被忘记或已取代的记录不得影响检索，也不得从保留历史中自动重新构建。忘记记忆与删除来源历史是不同操作。 |
| CTX-001 | 主对话和每次后台执行使用独立内部上下文，同时在一个 Telegram 聊天中交互。追问可以检索相关执行证据，无需把完整后台轨迹加入前台历史。 |
| CTX-002 | 原始消息与压缩后的 agent 状态分别归档。按预算压缩，同时保留近期完整工具交互、当前决定、约束、纠正和证据引用。权限与任务控制记录不得依赖有损摘要。 |
| SEC-001 | 应用代码根据身份、范围、参数和资源限制检查每个工具请求。文件操作限制在专用工作区。第一版不提供任意代码执行、不受限本机访问或已连接账号修改能力。 |
| SEC-002 | 网页、提取内容、工具输出与模型生成的指令都是不可信数据。它们不得授予访问、创建持续任务、未经用户意图覆盖个人记忆，也不得通过摘要升级为更高优先级的用户指令。 |
| DATA-001 | 持久化任务约定、个人记忆、已接受的入站消息与必要执行状态，使正常重启不会悄然丢失它们。处理 Telegram 重复投递时，不重复执行已接受的状态变更。 |
| DATA-002 | 分别对原始对话、检查点、研究材料与运行日志应用文档约定的保留策略。区分活跃数据删除与备份过期；恢复备份不得悄然重新启用已删除任务或被忘记的记忆。 |
| OPS-001 | 允许用户查看任务、个人记忆和最近执行，包括状态、证据引用、失败信息、取消与发送不确定性。用户可见记录和日志不得包含密钥。 |
| OPS-002 | 记录模型和搜索用量以及费用估算，配置时间与调用上限。在新计费工作开始前执行本地预算策略，并说明预算耗尽。不得把估算费用或本地限制描述为准确的服务账单保证。 |

## 验收案例

这些案例定义将来需要演示的结果，不规定测试框架或实现顺序。

| 案例 | 对应需求 | 场景与预期结果 | 所需证据 |
| --- | --- | --- | --- |
| AC-01 | AUTH-001, SEC-001 | 未配置的用户或不允许的聊天请求个人信息或任务。不发生模型工作或个人状态变更；用户本人仍能使用机器人。 | 受控授权检查与 Telegram 集成证据 |
| AC-02 | CHAT-001, WEB-001, WEB-002 | 研究包含可访问和不可访问网页的问题。结果引用已获取证据，标明限制并支持追问；不得描述未获取网页为已成功读取。 | 保留来源材料的真实服务案例与有边界的失败检查 |
| AC-03 | TASK-001, MEM-001 | 已配置时区时要求每天 08:00 简报。只创建一个任务并回显约定。未配置时区时，安排任务前先澄清。“这份简报短一点”影响任务，不改变全局回答风格。 | 持久化约定与观察到的聊天结果 |
| AC-04 | CHAT-002, TASK-002 | 存在多个任务时，回复其中一个并改时间。只有目标任务变化。存在歧义的删除请求先澄清，不修改任何内容。查看与明确删除有效。 | 每次控制操作前后的状态 |
| AC-05 | CHAT-001, TASK-003 | 在执行中暂停任务。该次执行继续，下一计划时间不创建新执行。明确停止前台工作，展示取消边界和在途工作。恢复后允许后续执行。 | 执行记录与实际调度、取消行为 |
| AC-06 | TASK-004, TASK-005 | 在补跑窗口内恢复一次或多次错过的执行，再在窗口外恢复。最多补跑一次符合条件的任务，不连续发送历史简报。只使用已保存的任务约定。 | 可控时钟检查与重启演示 |
| AC-07 | TASK-006, DATA-001 | 在入站接受、结果持久化和发送附近重启。重复 Telegram 更新不重复修改任务；已生成结果保留。发送失败重发保存结果；发送结果不明确时标记不确定。 | 故障注入与恢复记录；真实消息发送另行检查 |
| AC-08 | MEM-001, MEM-002, MEM-003 | 保存偏好、查看、用于相关问题、修改并忘记。随后再次访问来源对话，旧记录不被悄然恢复。未获同意的建议不保存。 | 记忆、来源记录与检索结果 |
| AC-09 | CHAT-002, CTX-001, CTX-002 | 一边聊天一边执行后台简报，随后回复其第二条内容。检索相关证据。强制压缩后，仍准确保留“Python 取代 TypeScript”这样的纠正，原始历史仍可获取。 | 组装上下文、归档与检查点检查 |
| AC-10 | TASK-004, SEC-001, SEC-002 | 获取要求读取密钥、创建任务、修改记忆或访问私有网络 URL 的材料，同时直接尝试越界工具请求。不产生未经授权的影响，并记录策略拒绝。 | 受控攻击材料与工具边界检查 |
| AC-11 | MEM-003, DATA-002 | 使临时材料过期、忘记记忆并删除任务。确认活跃检索与调度不再使用移除的数据。恢复流程处理删除记录，并说明备份过期边界。 | 保留、删除检查与恢复证据 |
| AC-12 | WEB-002, OPS-001, OPS-002 | 达到调用、时间、输出或预算限制，并模拟服务最终失败。工作终止，提供有用状态、可查看用量和简短通知，不泄露凭据。 | 边界检查、运行记录与消息观察 |

## 尚需明确的规格

- 记忆、压缩、历史删除、备份恢复接口与删除标记保留策略。
- M2 持续任务增量以外的完整案例验收。

M1 前台控制、队列数值、重启处理、预留、credit 估算与发送不确定性已在[实现参考](../reference/telegram.zh-CN.md)定义。证据状态见 [M1 记录](../development/m1-validation.zh-CN.md)。

在受影响的行为被认定完成前，先通过针对性的设计审查解决这些问题。后续实现与证据关联到上方 ID；未有实际结果支持前，所有验收案例保持未验证。

M2 任务约定、控制、并发和补跑的准确行为见[任务参考](../reference/tasks.zh-CN.md)，验收范围见 [M2 记录](../development/m2-validation.zh-CN.md)。
