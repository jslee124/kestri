# ADR-0006：保守本地数据恢复

[English](0006-conservative-data-recovery.md) · [文档导航](../README.zh-CN.md)

更新：2026-10-02。

状态：已接受，在 M4 实现。

## 背景

DATA-002 与 AC-11 要求恢复旧备份不能静默复活后来忘记的事实或删除的任务。快照自身无法知道之后发生的撤销。单独撤销日志会给单主人产品引入存储一致性、备份顺序、迁移与故障复杂度。

## 决策

采用有界私有逻辑业务/证据快照，排除模型 checkpoint/思考状态及密钥，只恢复到同主人空目标。隔离所有导入的活跃记忆，暂停所有导入的未删除任务，检索/调度需主人重新明确授权。重置上下文并隔离未完成执行/发送/费用预留。恢复后首次 Telegram 启动丢弃积压命令，先通知边界再接受新请求。

空闲时按类别清理并物理删除证据，同时清除内容和使图状态失效。保留最小去重、撤销、身份与费用标记。备份过期独立于活跃数据删除，详细规则见[数据参考](../reference/data-lifecycle.zh-CN.md)。

## 替代方案和后果

直接回放快照简单，但无法安全处理后来撤销。独立追加撤销日志可保留部分活跃状态，却需要另一套可信持久权限与核对协议。完整 PostgreSQL dump 会保留内部执行状态，需要独立安全迁移/撤销程序。在复杂度有实际价值前暂缓。

本方案牺牲连续性：仍需要的旧记忆须重新输入，旧任务须显式恢复。恢复启动边界的积压消息会丢弃。备份是未加密的私有本地数据，不能认证恶意作者，有大小/schema 限制，需要主人管理异地副本。受控失败回滚；文件工作时突然中断可能遗留孤立证据。明确这些边界，不宣称普遍恢复保证。

## 重新评审条件

多用户/云端、大数据量、独立代码沙箱、加密或远程备份、选择性持续恢复、schema 升级或外部撤销日志需要重新评审。不允许从模型摘要或旧快照自动恢复权限。
